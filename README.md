# line-bot-realestate

不動産初期対応 LINE Bot（Render.com / Node.js）

## Google ビジネスプロフィール 週3回投稿（LINE承認制）

マイベストプロの売却・相続コラムを、Google用の短文にして週3回（火・金・日 朝9時）投稿します。
**投稿前に必ずスタッフが LINE で承認**します。

```
GitHub Actions（火・金・日9時）→ ボット → Claudeが要約 → LINEに投稿案＋ボタン
        → 「承認して投稿」→ Google ビジネスプロフィールに投稿
```

### 毎回の運用
1. スプレッドシート **「GBP投稿」タブ**（初回起動時に自動作成）に、記事を1行ずつ追加
   - B：タイトル / C：元文章（マイベストプロの本文を貼り付け）/ D：参考URL（ボタンの遷移先。空ならトップページ）
   - E（状態）は空欄のままでOK。自動で「承認待ち → 投稿済」に変わります
2. 火・金・日の朝にLINEへ投稿案が届く → **承認して投稿 / 作り直す / スキップ**
3. ネタが残り2本以下になるとLINEで通知されます
4. 今すぐ案を作りたいときは、管理者のLINEから `#gbp案` と送信

### セットアップ
**① Google Business Profile API の利用申請（最初に。承認まで日数がかかります）**
Google Cloud でプロジェクトを作り、「Business Profile API」の利用申請フォームを提出します。
承認前でも、手順②〜④だけで「テスト動作」（承認ボタンまで確認、Googleには投稿しない）ができます。

**② Render の環境変数**

| 名前 | 内容 |
|---|---|
| `ANTHROPIC_API_KEY` | 要約用の Claude API キー |
| `CRON_SECRET` | 長いランダム文字列（下の GitHub Secrets と同じ値） |
| `GBP_CLIENT_ID` / `GBP_CLIENT_SECRET` | Google の OAuth クライアント |
| `GBP_REFRESH_TOKEN` | `node scripts/gbp-refresh-token.js` で取得 |
| `GBP_ACCOUNT_ID` / `GBP_LOCATION_ID` | 投稿先の数字ID（API の accounts / locations 一覧で確認） |
| `GBP_DEFAULT_URL` | 任意。既定は `https://creacross.jp/` |
| `GBP_CLAUDE_MODEL` | 任意。要約に使うモデル |

`GBP_*` が未設定の間は、承認しても実際には投稿されません。

**③ GitHub の Secrets（Settings → Secrets and variables → Actions）**
`BOT_URL`（例：`https://xxxx.onrender.com`）と `CRON_SECRET`

**④ 動作確認**
GitHub の Actions タブで「GBP投稿案の作成」を手動実行 → LINEに案が届けばOK

### 投稿に添える画像（タイトル入りカード画像）
投稿には、**記事タイトル入りのカード画像（1200×900）**が自動で付きます。LINEの承認画面にも、同じ画像が表示されます。
- 画像は、ボットが記事のタイトルから自動で作ります（日本語フォント同梱。外部サービス不要）
- 左上のラベルと下部の社名は、環境変数 `GBP_IMAGE_LABEL`（既定「売却・相続コラム」）と `GBP_IMAGE_FOOTER`（既定「株式会社クレアクロス」）で変更できます
- **自分で用意した写真を使いたい記事**は、シートの **J列「画像URL（任意）」** に `https://` のURLを入れると、自動作成の代わりに、そちらが使われます（自社サイトにアップロードした画像のURLなど。JPG/PNG、5MB以下、横長4:3が目安）
- 画像を付けたくないときは、Render の環境変数に `GBP_AUTO_IMAGE=off` を入れます
- 画像が原因でGoogleに断られたときは、**文章のみで1回だけ再試行**し、LINEにその旨を知らせます
- 画像のURLには署名があり、第三者が勝手に画像を作ることはできません（`CRON_SECRET` で署名）

### スリープ対策（承認ボタンが無反応になるのを防ぐ）
Render の無料プランは **15分アクセスがないとスリープ**し、復帰に約1分かかります。一方 **LINE の webhook は2秒で応答がないとタイムアウト**するため、スリープ中に承認ボタンを押すと操作が届かず「無反応」になります。

対策として、**営業時間（既定：日本時間 8〜20時）の間だけ、ボットが自分自身へ10分おきにアクセスして起きたままにします**。夜間はスリープして、無料枠を節約します。

| 環境変数 | 既定 | 内容 |
|---|---|---|
| `KEEPALIVE` | （未設定） | `off` にすると、この仕組みを止めます |
| `KEEPALIVE_HOURS` | `8-20` | 起こしておく時間帯（日本時間）。`22-6` のように日をまたぐ指定も可 |
| `KEEPALIVE_INTERVAL_MIN` | `10` | アクセス間隔（分）。15分以上は指定できません（眠ってしまうため） |

- **無料枠にご注意ください。** 起きている時間は Render の無料枠（**月750時間・ワークスペース内の全無料サービスで共有**）を消費します。8〜20時なら月およそ360時間です。他にも無料サービスを動かしている場合は、合計が750時間を超えないか、Render の使用量をときどき確認してください。超えると、月末まで**すべての無料サービスが停止**します。
- 時間帯を狭めたいときは、`KEEPALIVE_HOURS` を `9-18` などに変更します。
- 保険として、GitHub Actions（`keepalive.yml`）が 8・10・12・14・16・18時にもアクセスします。
- それでも返信が間に合わなかった場合に備え、**返信できないときは同じ内容をプッシュ通知で送ります。**

### 安全のための仕組み
- 承認なしでは投稿されません（承認できるのは `ADMIN_USER_IDS` のスタッフのみ）
- 投稿文を自動チェック（URL・電話番号・「絶対」「最安」「日本一」などの誇大表現・1,500文字超）。問題があるときはLINEに警告を表示
- 元文章にない事実や数字を足さないよう Claude に指示。法律・税務は一般論にとどめ、専門家確認を促す文面にしています
- 二重投稿防止：ボタン連打は無視、投稿失敗時は自動再試行せず「エラー」で停止
